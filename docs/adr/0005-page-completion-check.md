# ADR-0005: ページの完了条件は Vitest のテストとして検査し、GitHub Actions の公開前に走らせる。「3画面以内」は検査しない

- **状態**: 有効
- **決定日**: 2026-09-12
- **関連**: Issue #8 / [spec.md](../../specs/001-learning-site-first-page/spec.md)（FR-023 / SC-002 / SC-009） / [ADR-0004](./0004-quiz-data-model.md)

## 背景（何に困っていたか）

spec の FR-023 は「公開されるページがクイズ3問・最終確認日・出典リンクを持つことを**機械的に
検査**し、欠けていれば公開処理を失敗させる。人の目視確認に頼らない」と定める。決めるべきは3つ。

1. **何が検査を実行するか**（テストなのか、ビルドの一部なのか、CI の独立したステップなのか）
2. **いつ止めるか**（push 前か、main に入った後の公開直前か）
3. **憲法 II の「本文はスクロール3画面以内」も機械で検査するのか**

3 は厄介だった。**機械に「3画面」は測れない** — 画面の高さは端末ごとに違い、Mermaid 図の
描画後の高さはビルド時に分からない。測れるのはせいぜい文字数で、それは3画面とは別の量である。

## 決定

**1. 検査は Vitest のテストとして書く。** 専用のビルドプラグインやスクリプトにはしない。

**2. 検査する項目は FR-023 の3つ＋ [ADR-0004](./0004-quiz-data-model.md) が生んだ2つ。**

| 検査 | 落とす条件 |
|---|---|
| クイズ3問 | `quiz` が無い / 3件でない / `choices` が4件でない / `answer` が 0〜3 でない |
| 最終確認日 | `lastVerified` が無い / `YYYY-MM-DD` 形式でない |
| 出典リンク | 本文に外部リンクが1本も無い |
| ページのキー | `quizId` が無い / 他ページと重複している |
| 目次との整合 | 目次からリンクされているのに上のどれかを満たさない（FR-005 / FR-021） |

**3. GitHub Actions で、サイトをビルドして公開する前に `npm test` を走らせる。**
落ちたら公開しない（SC-009）。

**4. 「スクロール3画面以内」は機械検査しない。** 公開前に自分の目で見る。文字数の上限も設けない。

## 理由

**Vitest のテストにしたのは、憲法 IV と同じ土俵に載せるため。** 憲法 IV は「テストが緑でないものは
マージしない」と定めている。検査を独立したスクリプトにすると、テストとは別に「もう1つ守るべきもの」
が増え、手元で回す習慣が2つに割れる。**`npm test` 一本に集約すれば、ローカルでも CI でも同じ
コマンドで、同じ理由で止まる。**

**公開前の CI を最後の砦にしたのは、pre-push フックが `--no-verify` ですり抜けられるから。**
SC-009 は「検査をすり抜けて公開されるページが0本」を求めている。手元のフックは早く気づくための
道具であって保証ではない。**保証は main に入ったあと、公開の直前に置く。**

**3画面を検査しないのは、代理指標が嘘をつくから。** 文字数を上限にすると、図が多くて文章の
短いページ（＝憲法 II が理想とする形）が通り、図の無い長文ページが 2999 字ですり抜ける。
**憲法が守りたいものと逆を向いた指標は、守っている気分だけを作る。**
受け入れたコスト: 「気力が続かないと見なくなる」問題は残る。それは検査ではなくページ分割の
習慣で対処する。

## 検討した代替案

| 案 | 内容 | 却下理由 |
|---|---|---|
| A | 独立した検査スクリプト（`npm run check:pages`） | 守るべきコマンドが2つに増え、手元で回す習慣が割れる |
| B | VitePress のビルドプラグインとして検査し、ビルドを落とす | 検査の失敗がビルドエラーに紛れて読みにくい。テストとして単独で回せない |
| C | `.githooks/pre-push` だけで検査する | `--no-verify` ですり抜けられるため SC-009 の保証にならない（早期警告としては将来足してよい） |
| D | 本文の文字数上限（例 3000 字）を検査に足す | 文字数と3画面は一致しない。図の多い短いページを落とし、図の無い長文を通す |
| E | 描画後の高さを実ブラウザで測る | 1人用の学習ノートに対して仕組みが重すぎる。端末差で結果が揺れる |

## 結果（この決定が生むもの）

- 守るべきコマンドが `npm test` 1本になる
- 未完成のページは公開されない（SC-002 / SC-009 が仕組みで担保される）
- **検査できるのは「形式」だけ**であることが確定した。「出典が適切か」「記述が正しいか」は
  **人の仕事のまま**（憲法 I は機械化されない）
- **受け入れたコスト**: 3画面超過は自分で気づくしかない

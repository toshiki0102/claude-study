# ADR-0008: 図の色は「役割」で決めて各図の classDef に書き、ブランド色は CSS 変数、要点は `::: tip` にする

- **状態**: 有効
- **決定日**: 2026-09-13
- **関連**: Issue #30 / [ADR-0006](./0006-mermaid-rendering.md)（Mermaid の描画方法） / [契約: ページの frontmatter](../../specs/001-learning-site-first-page/contracts/page-frontmatter.md)

## 背景（何に困っていたか）

公開3ページを通して見た本人の評価は「文字の長さはいいが、**色合いがなくて見にくい**」。
図・要点カード・表・ページ全体の4つすべてが対象だった。

- Mermaid は既定テーマで、箱がすべて同じ灰色。「毎回入るもの」「積もるもの」「戻るもの」の
  区別が図の形だけに頼っていた
- 要点カードは `>` 引用で、本文と同じ見た目
- 表のヘッダーは無色、「残る／消えうる」の対比列も同色
- VitePress のブランド色は既定のまま

憲法 II「図が主役」は、図が見分けられて初めて成り立つ。制約は、ページを書く負担を
増やさないこと、ライト／ダーク両方で読めること、ADR-0006 の描画方法（`vitepress-plugin-mermaid`）
を変えないこと。

## 決定

1. **図の箱は「役割」で塗る。役割は4つ、サイト共通。** 各図の末尾に `classDef` を書き、
   箱を `class` で割り当てる。塗り・枠・文字色をすべて明示する（ダークでも同じに見えるように）。

   | 役割 | クラス | 意味 |
   |---|---|---|
   | 毎回入るもの・入力 | `fixed` | システムプロンプト、ツール定義、CLAUDE.md、prompt |
   | 積もるもの・処理中 | `accum` | 会話履歴、tool_use → tool_result のループ、評価 |
   | 戻るもの・結果 | `result` | 最終回答、親に戻る tool_result、要約 |
   | 境界・特別な操作 | `edge` | 圧縮、fork、上限 |

2. **ブランド色は藍。** `docs/.vitepress/theme/custom.css` で `--vp-c-brand-*` を上書きする
   （ライト `#4338ca`、ダーク `#a5b4fc`）。リンク・サイドバーの現在位置・要点カードがこの色になる。
3. **要点カードは `::: tip 要点`。** VitePress のカスタムブロックを使い、CSS で左に帯を足す。
4. **表はヘッダーに淡いブランド色。** 対比の表は見出しに `.keep` / `.gone` を付けて緑と薔薇にする
   （図の `result` / `edge` と同じ意味）。
5. Mermaid のプラグイン設定（`themeVariables`）には**線と枠のトーンだけ**を置く。役割色は置かない。

## 理由

**役割色を図ごとの classDef に置くのは、意味が図ごとに違うから。** グローバルなテーマは
「1番目の箱は青」のような位置しか決められず、「この箱は積もるもの」という意味は表せない。
意味を持つ色は、意味を知っているページ側が割り当てるしかない。その代わり**4色と意味は
サイト共通に固定**し、ページごとに勝手な色を増やさない。読者は3ページ目で色の意味を覚える。

**ブランド色は CSS 変数1か所。** VitePress は `--vp-c-brand-*` からリンク・サイドバー・
`tip` ブロックの色を派生させる。1か所を変えれば全部が揃い、コンポーネントを書く必要が無い。

**要点を `::: tip` にしたのは、書く負担が `>` と変わらないから。** Vue コンポーネントを
作れば自由度は上がるが、ページの型は「読み返して分かる」ためのもので、飾りではない。

受け入れたコスト:

- 各図に `classDef` 4行と `class` 数行が増える（図の本体より長くなることがある）
- 塗り色を明示するため、Mermaid のダークテーマの配色とは一致しない（淡い塗りに濃い文字。
  読めることを優先した）
- 対比の表は Markdown だけで書けず、見出しに `<span>` が要る

## 検討した代替案

| 案 | 内容 | 却下理由 |
|---|---|---|
| A（採用） | 役割色を各図の classDef、ブランド色を CSS 変数、要点を `::: tip` | — |
| B | Mermaid の `themeVariables` だけで色を付ける | 位置でしか色が決まらず「役割」を表せない。図が変わるたび意味がずれる |
| C | 各図の先頭に `%%{init: {...}}%%` でテーマを書く | classDef と同じ長さで、しかも役割ではなくテーマ全体の指定。読みにくい |
| D | 要点カードを Vue コンポーネント（`<KeyPoints>`）にする | 書く側の負担が増え、Markdown だけで完結しなくなる。`::: tip` で足りる |
| E | 表を HTML で書いて列に色を付ける | 表全体が HTML になり差分が読めない。見出しの `<span>` だけで対比は伝わる |

## 結果（この決定が生むもの）

- 3ページのどの図でも「同じ色＝同じ意味」。これがこのサイトの見た目の特徴になる
- 新しいページは契約の「形」に従えば自動的に同じ配色になる
- 宿題: 役割が4つで足りなくなったら（例: 「外部に出ていくもの」）、この ADR を置き換える
  新しい ADR で色を追加する。勝手に5色目を作らない

# ADR-0003: ADR 検査から `constitution.md` を除外する

- **状態**: 有効
- **決定日**: 2026-08-29
- **関連**: Issue #5 / [ADR-0002](./0002-constitution-four-principles.md)（宿題として記載） /
  `.githooks/checks/upstream-override-adr.sh`

## 背景（何に困っていたか）

`upstream-override-adr.sh` は変更ファイルを `^(\.specify/|\.claude/skills/)` で判定し、
新規 ADR が無ければ push を止める。上流（Spec Kit）から再生成される領域を守るための検査で、
これ自体は正しく働いている。

問題は `.specify/memory/constitution.md` がこの正規表現に含まれることだった。**このファイルは
「プロジェクト側が埋めること」を前提に置かれたテンプレート**で、埋めるのは上流に逆らう行為では
ない。それなのに、原則を1行直すだけでも ADR を要求される。

実際に ADR-0002（憲法の制定）で踏んだ。あのときは ADR を書く理由が別にあったので通ったが、
**この誤検知を放置すると「憲法を触る＝ `--no-verify` を打つ」が習慣になる。** そうなると、
本当に止めたい変更（`templates/` や `scripts/` の書き換え）まで同じ手癖で素通りする。
検査は、誤検知が続くと信用を失って迂回されるという形で壊れる。

## 決定

**`.specify/memory/constitution.md` だけを検査対象から除外する。**

```bash
EXCLUDE_RE='^\.specify/memory/constitution\.md$'
```

行末を `$` で閉じ、**このファイル1つだけ**を対象にする。同じコミットで `.specify/` の他の
ファイルも触っていれば、従来どおり止まる。

あわせて憲法 Governance の「pre-push が ADR の同伴を機械的に検査する」という記述が事実と
食い違うことになるため、v1.0.1 として訂正した（機械的な強制は無く、自分で守る）。

## 理由

**検査の価値は「止めるべきものを止めること」ではなく「止まったら本当に考えること」にある。**
誤検知が日常化した検査は、迂回コマンドを反射で打つ訓練にしかならない。除外して精度を上げる
ほうが、検査全体の実効性は高い。

**犠牲にしたもの**: 憲法の改正時に ADR が機械的には強制されなくなった。憲法自身の Governance
が「改正は理由を ADR に残す」と定めているが、これは今後**自分で守る規律**になる。誤検知を
減らす代わりに、規律を1つ人間側へ移した取引だと理解している。

## 検討した代替案

| 案 | 内容 | 却下理由 |
|---|---|---|
| A | 現状維持（憲法を触るたび ADR を書く） | 誤字修正でも ADR が要る。`--no-verify` が習慣化し、検査全体が形骸化する |
| B | `.specify/memory/` ディレクトリごと除外 | 将来この配下に上流由来のファイルが増えたとき、黙って素通りする。今わかっている1ファイルだけに絞るほうが安全 |
| C | 検査そのものを廃止する | `templates/` `scripts/` が上流アップグレードで黙って戻る問題は実在する。検査は残す価値がある |
| D | 除外せず、ADR 不要な変更用のフラグを別に用意する | `--no-verify` が既にその役割。フラグを増やしても迂回の習慣化は変わらない |

## 結果（この決定が生むもの）

- 憲法の改正で push が止まらなくなり、**検査が止めたときは本当に考えるべきとき**になった。
- テストが 8 件 → 11 件に増えた。除外の境界（他ファイル同伴・`constitution-template.md`）を
  固定したので、今後正規表現を触っても壊れたら気づける。
- 受け入れたコスト: **憲法改正時の ADR は機械的に強制されない。** 守るのは自分。

# ADR — 意思決定記録（Architecture Decision Records）

**「なぜそうしたか」を残す場所。** コードとドキュメントは *いまどうなっているか* は
語るが、*なぜ他の選択肢を捨てたか* は語らない。それを失うと、同じ議論を何度もやり直し、
理由を知らないまま決定を覆してしまう。ADR はその背景・理由・トレードオフを1決定=1ファイルで残す。

## 何をここに書き、何を書かないか

| 書く | 書かない（＝所有者が別にある） |
|---|---|
| 個別の判断の**背景・理由・却下した代替案** | 原則・規約 → `.specify/memory/constitution.md` |
| そのとき何を天秤にかけたか（トレードオフ） | いまの構成・手順 → `README.md` / `CONTRIBUTING.md` |
| 決定の結果として何が起きるか | やること（進捗）→ GitHub Issues |

**ADR は現状の説明書ではない。** 手順や構成が変わったら所有者ファイルを直し、ADR は
書き換えず「置き換えられた」ことだけ追記する（後述）。

## ルール

- **1決定 = 1ファイル**、`NNNN-短い説明.md`。番号は連番で**再利用しない**。
- **決定後の ADR は書き換えない**（誤字修正を除く）。判断が変わったら**新しい ADR を書き**、
  古い方の `状態` を `置き換え済み（ADR-NNNN による）` にして相互リンクする。
- 書式は [`template.md`](./template.md)。**理由と代替案の欄を空にしない**（それが本体）。
- 新規追加時は下の一覧に1行足す。

## 必ず ADR が要る場合: 外部のデフォルトに逆らうとき

`.specify/`（Spec Kit のテンプレート）と `.claude/skills/` は、**外部から再生成・更新される
領域**。ここへの変更は、上流のアップグレードで黙って元に戻されうる。しかも戻っても
ビルドは壊れないので、**気づく手立てが無い**。

そのため **この2つの領域を変更するときは ADR を書く**。`.githooks/pre-push` が機械的に
検知して push を止める（`checks/upstream-override-adr.sh`）。上流の更新をそのまま受け入れる
など ADR が不要な変更では `git push --no-verify` で通す。

**例外: `.specify/memory/constitution.md`。** このファイルはプロジェクト側が埋める前提の
テンプレートなので、検査対象から外してある（[ADR-0003](./0003-exclude-constitution-from-adr-check.md)）。
ただし**憲法の改正時に ADR を書く規律は変わらない** — 機械が止めなくなっただけで、自分で守る。

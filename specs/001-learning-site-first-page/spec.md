# Feature Specification: 学習ノートサイト — 1本目のページを公開まで通す

**Feature Branch**: `feat/site-spec`

**Created**: 2026-08-29

**Status**: Draft

**Input**: Issue #4 / ブレインストーミングでの合意（2026-08-29）

## Clarifications

### Session 2026-08-29

- Q: 成績と設問をどう結びつけるか（設問が編集されたときの扱い） → A: 問題文から自動で識別子を算出する。設問を編集すると別問題とみなされ、その問題の成績だけリセットされる
- Q: 正誤が表示された後、選択肢を選び直せるか → A: 選び直せない。1問につき1回で確定し、やり直しは「間違えた問題だけもう一度」から行う
- Q: ページの完了条件（クイズ3問・最終確認日・出典）を誰が保証するか → A: CI が機械的に検査し、満たさないページがあればビルドを落とす

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 公開されたページを読んで概要をつかむ (Priority: P1)

読者（＝作者本人）が公開 URL を開くと、冒頭の要点3行で「このページが何の話か」を数秒で
つかめる。続く図で全体の形を見て、本文で図を補う。読み終えるまでにスクロールは3画面まで。
ページには「いつ時点の情報か」と出典が書かれているので、古びていないかを自分で判断できる。

**Why this priority**: これ単体で価値が成立する最小の塊。図と要点だけでも「読み返して思い出す」
という目的を果たす。クイズも成績も無くても、公開されたページ1本には意味がある。

**Independent Test**: 公開 URL を開き、要点3行・図・最終確認日・出典が表示され、本文が3画面に
収まっていることを確認するだけでテストできる。

**Acceptance Scenarios**:

1. **Given** ページが公開されている、**When** 読者が URL を開く、**Then** 冒頭に要点が3行表示される
2. **Given** ページを開いている、**When** 本文を読み進める、**Then** 概念を説明する図が表示されている
3. **Given** ページを開いている、**When** 情報の新しさを確かめたい、**Then** 最終確認日と出典リンクが見つかる
4. **Given** 未着手のページがある、**When** 読者が目次を見る、**Then** 未着手ページへのリンクは存在しない

---

### User Story 2 - クイズ3問で理解を確かめる (Priority: P2)

ページを読み終えた読者が、末尾の4択クイズ3問に答える。各問はそのページの本文だけで答えられる。
選択すると正誤がその場で分かり、間違えた問題では正解が示される。「読んで分かった気になった」
だけなのか、実際に理解できたのかがその場で判明する。

**Why this priority**: 憲法 III が定めるページの完了条件そのもの。ただし US1 が無いと成立しない
（問う対象の本文が必要）ため P2。

**Independent Test**: ページ末尾で3問に回答し、正誤と正解が表示されることを確認する。成績の
保存が無くてもテストできる。

**Acceptance Scenarios**:

1. **Given** ページ末尾のクイズ、**When** 読者が選択肢を選ぶ、**Then** その問題の正誤が表示される
2. **Given** 正誤が表示された問題、**When** 別の選択肢を選ぼうとする、**Then** 選び直せない
3. **Given** 誤答した問題、**When** 正誤が表示される、**Then** 正解が示される
4. **Given** 3問すべてに回答した、**When** 採点が終わる、**Then** 何問正解したかが分かる

---

### User Story 3 - 間違えた問題だけをやり直す (Priority: P3)

読者が後日ページを再訪問すると、前回の成績が残っている。間違えた問題があれば「間違えた問題
だけもう一度」で再挑戦でき、正解できたら記録が更新される。復習の対象が自動的に絞られるので、
すでに分かっている問題を解き直す無駄が無い。

**Why this priority**: 憲法 III の「間違えた問題を再出題する」を満たす部分。US1・US2 が
動いていれば後から足せる。

**Independent Test**: 1問わざと間違えてページをリロードし、成績が残っていること、再挑戦で
その問題だけが出ることを確認する。

**Acceptance Scenarios**:

1. **Given** クイズに回答した、**When** ページをリロードする、**Then** 前回の正誤が残っている
2. **Given** 間違えた問題がある、**When** 再挑戦を選ぶ、**Then** 間違えた問題だけが出題される
3. **Given** 再挑戦で正解した、**When** 採点される、**Then** その問題の記録が正解に更新される
4. **Given** 全問正解している、**When** ページを開く、**Then** 再挑戦の導線は示されない

---

### Edge Cases

- **端末内の保存が使えない**（プライベートウィンドウ、ブラウザ設定で保存を禁止、保存領域の
  読み書きが例外を投げる）: クイズは最後まで解け、採点も表示される。成績が残らないだけで、
  ページが壊れたり操作不能になったりしない。
- **保存されていた成績が壊れている・古い形式**: 読み取れない記録は無視し、未回答として扱う。
  エラー表示でページを止めない。
- **未回答のまま採点しようとした**: どの問題が未回答かが分かる。
- **同じページを複数のタブで開いて別々に回答した**: 後から保存された結果が残る。整合のための
  同期はしない。
- **設問を編集した（誤字修正を含む）**: その設問は別の設問として扱われ、成績がリセットされる。
  他の2問の成績は影響を受けない。
- **クイズを3問作れないページ**: 未完成として公開しない。目次からもリンクしない。
- **本文がスクロール3画面を超えた**: 憲法 II 違反として、公開前に分割する。

## Requirements *(mandatory)*

### Functional Requirements

**ページの型**

- **FR-001**: 各ページは冒頭に要点を3行で表示しなければならない。
- **FR-002**: 各ページは、説明する概念の図を含まなければならない。図が中心で、文章はその補足
  として書かれる。
- **FR-003**: 各ページは末尾に4択クイズを3問持たなければならない。
- **FR-004**: 各ページは1つの概念だけを扱い、本文はスクロール3画面以内に収まらなければならない。
- **FR-005**: クイズ3問を持たないページは公開してはならない。目次からもリンクしてはならない。

**正確さ**

- **FR-006**: 各ページは「最終確認日」を表示しなければならない。
- **FR-007**: 変化しうる記述（挙動・仕様・オプション名など）には出典へのリンクを添えなければ
  ならない。
- **FR-008**: 公式の情報で確認できない記述は、「未確認」と明示するか、書かない。

**クイズ**

- **FR-009**: 各設問は、そのページの本文だけで答えられなければならない。外部知識を要求しない。
- **FR-010**: 読者が選択肢を選ぶと、その場で正誤が示されなければならない。
- **FR-011**: 1つの設問への回答は**1回で確定する**。正誤が示された後、その場で選び直すことは
  できない。やり直しは「間違えた問題だけもう一度」からのみ行える。
- **FR-012**: 誤答した問題では正解が示されなければならない。
- **FR-013**: 3問すべての回答後、何問正解したかが示されなければならない。

**成績**

- **FR-014**: 成績は読者の端末内にのみ保存されなければならない。外部へ送信してはならない。
  アカウント登録を求めてはならない。
- **FR-015**: 保存されるのは設問ごとの最新の正誤である。過去の履歴は保持しない。
- **FR-016**: 再訪問時、保存されている成績が復元されなければならない。
- **FR-017**: 間違えた問題がある場合、それだけを再出題できなければならない。再出題はその
  ページ内で完結する。
- **FR-018**: 成績は、どのページのどの設問かを識別できる形で保存されなければならない
  （将来ページ横断で集計できるようにするため。集計機能そのものは今回作らない）。
- **FR-019**: 設問の同一性は**問題文の内容から決まる**。設問を編集すると別の設問とみなされ、
  その設問の成績だけがリセットされる。出題順を入れ替えても、成績は問題文についてくる。
- **FR-020**: 端末内の保存が利用できない環境でも、クイズの回答と採点は動作しなければならない。

**目次と公開**

- **FR-021**: 目次には2本柱（「使い方」「仕組み」）の枠を示す。未着手のページはリンクしない。
  「準備中」の空ページを作らない。
- **FR-022**: 変更が main に取り込まれると、公開サイトが更新されなければならない。
- **FR-023**: 公開されるページが「クイズ3問・最終確認日・出典リンク」を持つことを、**機械的に
  検査しなければならない**。1つでも欠けていれば公開処理を失敗させる。人の目視確認に頼らない。

### Key Entities

- **ページ**: 1つの概念の解説。要点3行、図、本文、最終確認日、出典、クイズ3問を持つ。
- **設問**: 4択の問い。問題文、選択肢4つ、正解を持つ。**設問の識別子は問題文から決まる**
  （手で振らない）。
- **成績記録**: 「どのページのどの設問か」に対する最新の正誤。読者の端末内にのみ存在する。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 読者が公開 URL を開いてから、そのページが何の話かを把握するまで **60秒以内**
  （要点3行と図だけで足りる）。
- **SC-002**: 公開されているすべてのページが、クイズ3問・最終確認日・出典を持つ（**100%**）。
  この 100% は人の確認ではなく**機械的な検査で保証される**。
- **SC-003**: 公開されているすべてのページの本文が、スクロール**3画面以内**に収まる。
- **SC-004**: クイズに回答した後でページを閉じて開き直したとき、**成績が残っている**。
- **SC-005**: 端末内の保存が使えない環境でも、**3問すべてに回答でき、採点結果が表示される**。
- **SC-006**: クイズの回答によって、読者の端末外へ送信されるデータが **0件**。
- **SC-007**: 目次からたどれるページのうち、未完成のものが **0本**。
- **SC-009**: 完了条件を満たさないページを公開しようとしたとき、**公開処理が失敗する**
  （検査をすり抜けて公開されるページが 0本）。
- **SC-008**: main への取り込みから公開サイトへの反映までが、**手作業なし**で完了する。

## Assumptions

- **読者は作者1人。** 同時利用者数・負荷・多言語対応は考慮しない。
- **端末をまたいだ成績の同期はしない。** 別の端末やブラウザでは成績は空から始まる。これは
  「サーバーを持たない」という制約の当然の帰結として受け入れる。
- **技術構成は決定済み。** 静的サイト生成・図の記法・公開先は憲法「技術と公開の制約」節が
  所有する。本仕様はそれを前提とし、再定義しない。
- **1本目の題材は「エージェントループ」**（入力 → 推論 → ツール実行 → 結果を戻す → 繰り返す）。
  内部挙動は公式情報が薄い領域であり、確認できない部分は書かないため、**1本目は薄いページに
  なる可能性がある。それは仕様どおりの結果である。**
- **回答は1回で確定。** 正誤が見えた後に選び直せると記録が必ず全問正解になり、成績が理解の
  記録でなくなるため。
- **再挑戦の結果は上書き。** 同じ設問に何度答えても、残るのは最新の正誤のみ。
- **誤字修正でも成績はリセットされる。** 識別子を手で管理する手間を避けた代償として受け入れる。
  設問は3問だけで、記録の重みも小さいため。
- **全問正解している間は再挑戦の導線を出さない。**
- **文章は日本語。** 用語は初出時に英語を併記する。
- **公開は main への取り込みを起点とする。** ブランチ運用は `CONTRIBUTING.md` が所有する。
- **ページの完了条件は機械が検査する。** 憲法 IV の「テストが緑でないものはマージしない」を
  ページにも適用する。原則 I と III を「守る意思」ではなく仕組みにするため。

## Out of Scope（初回リリースに含めない）

- ページ横断の復習ページ（成績の保存形式だけ将来に備える）
- 間隔反復（SRS）による再出題日の計算
- サイト内検索、コメント、アクセス解析
- 2本目以降のページ
